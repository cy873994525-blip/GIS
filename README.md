- 图层显示与显隐控制

- 属性字段的新增与删除，并写入全部要素落库
- 多选要素后批量修改共有属性字段；删除要素前二次确认
- 坐标实时读数、图层统计与选中要素删除
- 响应式工作台布局，支持桌面与窄屏展示
- Python 后端保存 GeoJSON
- GeoJSON 导出
- GeoJSON 文件导入、数据集切换与文件元数据登记
- Shapefile ZIP/成套文件导入、SHP/DBF/PRJ/CPG 解析与 GeoJSON 转换
- PostGIS 留出后续扩展位置

## 运行

```bash
python server.py 8000
```

后端核心只使用 Python 标准库，Python 3.8 及以上都可以直接运行；可选安装 `pyproj`（`pip install pyproj`）后会自动启用“投影坐标 → WGS 84”转换，未安装时投影数据仍按平面坐标显示。

然后打开：

```text
http://127.0.0.1:8000
```

### 高德地图模式

不配置 Key 也能打开 Demo：经纬度数据默认显示 OpenStreetMap 的道路与地名底图，可在工具栏切换浅色显示，或用“定位”快速查看北京、上海、广州、成都。底图需要联网；模拟坐标和未转换的投影数据仍使用平面画布。底图只提供地理参照，不会自动把道路或兴趣点加入属性表。

如需启用**高德官方 JS API 2.0** 的标准地图、卫星与路网、实时路况和地点搜索，先在[高德开放平台](https://lbs.amap.com/api/javascript-api-v2/getting-started)申请 Web 端 Key 与安全密钥，再在启动服务的终端设置环境变量（不要写进仓库）：

```powershell
$env:GIS_AMAP_JS_KEY = "你的 Web 端 Key"
$env:GIS_AMAP_SECURITY_JS_CODE = "你的安全密钥"
python server.py 8000
```

两项都配置后，页面会自动加载官方地图；任一项缺失或加载失败时，仍保留 OpenStreetMap 详细底图与全部矢量编辑功能。安全密钥只留在本地 Python 服务端，浏览器通过同源 `/_AMapService/` 代理请求高德服务。当前服务仅监听 `127.0.0.1`；若日后公开部署，还需加访问控制、请求限额并核对高德开放平台的使用要求。官方地图作为 Canvas 下方的底图，点线面与属性表仍由本 Demo 管理；地点搜索仅移动视图，不写入当前数据集。

## 操作说明

1. 在左侧设置要素名称和图层，再选择“画点 / 画线 / 画面”。
2. 画线和画面需要连续点击地图，可双击、按 `Enter` 或点击“完成绘制”；画面还可以点击起点闭合。开启“吸附”时，新节点及拖动中的节点会贴合可见要素的节点或边。
3. 使用“点选”或“框选”查看属性；点选或框选时按 `Shift` 加选、按 `Alt` 减选，`Ctrl` 可切换选中状态。框选按真实几何与选择框相交判断，不再只看外包矩形。单选后右侧表单按真实字段渲染，可直接改值并保存。
4. 画线或画面过程中可以撤销节点，也可以按 `Esc` 取消绘制。
5. “全图”会根据当前数据范围自动计算合适的视图。
6. 地图下方的“属性表”抽屉列出当前数据集的全部要素。双击任意单元格即可就地改值，`Enter` 或点击别处提交，`Esc` 取消；拖动“全部 / 仅选中”可以只看选中要素，搜索框按任意字段值过滤，行内 `Ctrl` / `Shift` 点击可以加选和范围选，并与地图选中状态联动。
7. 选中要素后切换到“编辑几何”：拖动方形手柄改变形状，拖动要素本体整体平移，双击边插入节点，`Alt` + 点击节点删除节点，`Ctrl+Z` 撤销上一步几何编辑，`Esc` 放弃本次拖动。每一步结束都会自动写回后端。
8. 属性表标题栏的“新增字段”可以为全部要素加一列，表头字段名旁的 `×` 可以把该列从全部要素中删掉。
9. 点击“打开真实地图示例”会导入一份标明为虚构要素的经纬度数据，并显示在线底图。也可用“导入地图数据”上传 WGS 84 的 GeoJSON 或 Shapefile。地图工具栏的 `＋`、`－`、鼠标滚轮和“全图”可控制视图，“地图：开 / 关”可切换底图；“详细地图 / 浅色地图”切换底图显示，“定位”可快速跳转城市。配置官方 Key 后还能切换卫星/路况图层和搜索地点。
10. 选中多个要素后，右侧可选择这些要素共有的属性字段并填写统一新值；确认后一次写入当前数据集。删除选中要素前会再次确认，取消不会修改数据。

默认在线底图使用 [OpenStreetMap 标准瓦片](https://operations.osmfoundation.org/policies/tiles/)，仅加载当前视野内的瓦片，遵守服务端缓存规则并在地图内保留版权署名；配置 Key 后使用高德官方地图。只有坐标值和数据集坐标系都符合 WGS 84 经纬度的数据才会叠加底图；模拟坐标和未转换的投影 Shapefile 继续在平面画布中显示，以免错位。纯图片和 GeoTIFF 暂未作为可编辑地图导入。

## A 组：后端文件数据模块（当前实现）

后端现在提供一个轻量的数据集目录。导入的文件会存放在运行时目录 `data/uploads/`，并自动登记文件元数据：

- `GET /api/datasets`：列出数据集、当前激活数据集和要素统计。
- `POST /api/datasets/import`：导入 GeoJSON/JSON、Shapefile ZIP 或成套 `.shp/.shx/.dbf/.prj/.cpg` 文件，并自动切换为当前数据集。
- `POST /api/datasets/{id}/activate`：切换当前数据集。
- `GET /api/datasets/{id}`：读取指定数据集和元数据。
- `DELETE /api/datasets/{id}`：删除非当前数据集，至少保留一个数据集。
- `GET /api/layers`：读取当前数据集，供地图显示。
- `POST /api/save`、`POST /api/features`：保存当前数据集或追加要素。
- `PUT /api/features/{id}`、`DELETE /api/features/{id}`：更新或删除当前数据集中的要素。
- `GET /api/export`：导出当前数据集。

导入和保存过程会检查文件大小、要素数量、要素 ID、几何类型、坐标数值和面环闭合情况；缺少 ID 的导入要素会由后端自动生成唯一 ID。Shapefile 导入既支持 ZIP，也支持在文件选择器中同时选择同名的 `.shp/.shx/.dbf/.prj/.cpg` 文件；直接选择成套文件时至少需要 `.shp/.shx/.dbf`，`.prj/.cpg` 为可选。ZIP 会自动忽略 `__MACOSX`、`._*` 等系统隐藏文件；如果 ZIP 中没有 Shapefile 但只有一个 GeoJSON/JSON 文件，也会按 GeoJSON 导入。后端读取 `.shp` 几何、`.dbf` 属性、`.cpg` 编码和 `.prj` 坐标系提示，并统一转换为内部 GeoJSON 数据集；空几何记录会被跳过。当前支持 Point、PolyLine 和 Polygon 三类 Shapefile，单个组件最大 20 MB。

前端的数据文件面板支持查看文件大小、来源格式、几何类型、bbox 和坐标系提示，并可切换或删除非当前数据集。

这部分已经形成“文件导入 → 格式校验/转换 → 元数据登记 → 数据集切换 → 地图读取 → 文件管理”的后端闭环。当前已增强 `.prj` 识别（区分地理/投影坐标系并提取规范名称与 EPSG），保留 Polygon 洞结构（内环），并在安装 `pyproj` 后自动把投影坐标转换为 WGS 84 经纬度（可叠加在线底图）；下一步可以继续扩展数据库存储。

### A 组本次工作详细记录

本次 A 组主要负责后端文件数据模块的完善，目标是让 Demo 能够接收真实 GIS 文件，将不同来源的矢量数据统一转换成系统内部使用的 GeoJSON，并交给前端地图进行显示和管理。具体完成内容如下。

#### 1. 完善 GeoJSON/JSON 数据导入流程

- 后端接收 `.geojson` 和 `.json` 文件，并检查文件是否为标准 `FeatureCollection`。
- 对导入数据中的 Feature、geometry、coordinates、属性字段和要素数量进行基本校验。
- 对缺少唯一 ID 的要素自动生成 ID，避免前端选中、修改和删除时无法定位对象。
- 导入成功后，将数据写入 `data/uploads/`，同时在数据集目录中登记文件名、数据大小、要素数量、几何类型、bbox、坐标系提示和创建时间。
- 导入的数据会自动设为当前数据集，前端地图随后重新读取并显示。

#### 2. 新增 Shapefile ZIP 导入

Shapefile 不是单独一个文件，而是由同名的 `.shp`、`.shx`、`.dbf` 文件组成，通常还会包含 `.prj` 和 `.cpg`。本次在不依赖第三方 GIS 库的情况下，使用 Python 标准库完成了基础解析：

- `.shp`：读取 Point、PolyLine 和 Polygon 的几何坐标。
- `.dbf`：读取属性表字段和值，并将属性挂接到对应 Feature。
- `.prj`：读取坐标系描述，记录为数据集的坐标系提示。
- `.cpg`：识别 UTF-8、GBK、GB2312 等常见编码，改善中文属性字段和中文属性值的读取。
- 支持 Polygon 的多个环，并在必要时转换为 `MultiPolygon`。
- 跳过 Shapefile 中的空几何记录，避免个别空记录导致整个图层无法导入。
- 对 ZIP 中的隐藏系统文件（如 `__MACOSX`、`._*`、`.DS_Store`）进行过滤。
- 当 ZIP 中只有一个 GeoJSON/JSON 文件而没有 `.shp` 时，也可以按 GeoJSON ZIP 进行导入。

导入后，Shapefile 不会直接以原始二进制文件参与前端绘制，而是被转换为标准 GeoJSON，再复用现有的数据集管理和地图渲染流程。这样可以保持前后端数据格式统一。

#### 3. 新增成套 Shapefile 文件直接导入

除了 ZIP 导入，前端文件选择器现在支持同时选择同名的：

```text
省级行政区.shp
省级行政区.shx
省级行政区.dbf
省级行政区.prj
省级行政区.cpg（可选）
```

前端会自动识别 `.shp` 主文件，并收集同名的配套文件，以 Base64 形式发送给后端。后端至少要求 `.shp`、`.shx`、`.dbf` 三个文件，`.prj` 和 `.cpg` 为可选文件。这样用户既可以上传 ZIP，也可以直接选择 GIS 软件导出的完整文件组。

#### 4. 完善数据集管理和前端反馈

- 数据文件面板显示当前数据集、数据来源格式、要素数量、几何类型、bbox 和坐标系提示。
- 支持在多个已导入数据集之间切换。
- 支持删除非当前数据集，避免误删当前正在使用的数据。
- 上传过程中显示“正在导入”状态，导入成功后显示要素数量和数据格式。
- 导入失败时直接显示后端返回的错误原因，例如缺少 `.shx` 或 `.dbf`、ZIP 中没有 `.shp`、文件格式不符合要求等。
- 上传期间暂时禁用文件选择控件，避免重复提交或同时导入多个文件造成状态混乱。

#### 5. 修复真实投影坐标数据显示问题

在使用桌面上的真实省级行政区 Shapefile 测试时，文件能够成功解析并显示 34 个面要素，但地图最初仍然是空白。排查后发现，数据使用的是投影坐标，坐标值达到数百万，例如：

```text
X 范围约为 -2578821 至 2092054
Y 范围约为 2367106 至 6385320
```

原地图的全图缩放函数将最小缩放比例限制为 `0.25`，不适合这种大范围投影坐标，导致要素被计算到画布可视区域之外。此次将缩放下限调整为更小的动态范围，使地图能够根据真实数据 bbox 自动适配。修复后，34 个省级行政区可以正常显示在画布中。

需要说明的是，当前版本已经可以读取并显示投影坐标，但 `.prj` 目前主要用于识别和提示坐标系，还没有完成 Albers 等投影坐标到 WGS 84 经纬度的转换。当前地图因此更适合作为文件导入、数据管理和几何显示 Demo；如果后续需要与在线底图叠加，还需要引入 `pyproj` 等工具完成 CRS/EPSG 转换。

#### 1. 把属性表做成底部全宽抽屉

右侧属性栏只有 326px 宽，放不下真实数据的多字段表格，因此把完整属性表移到地图下方，做成可折叠的全宽抽屉，交互方式对标 QGIS / ArcGIS。

原来右侧编辑表单固定显示“名称”和“图层”两个控件，其中图层是一个含 5 个固定 `<option>` 的下拉框。这个设计对导入数据是失效的：Shapefile 的 `properties` 里根本没有 `layer` 字段（只有 DBF 的真实字段），字段名也不在固定选项里，赋值后会被静默清空。

现在改为按选中要素的真实字段动态渲染，一行一个输入框；`layer` 仍然用 `<input list="layerOptions">` 加由现有图层名填充的 `<datalist>`，既能选已有图层，也能直接输入新图层名。导入数据因此第一次可以在右侧正常编辑。

#### 3. 新增几何编辑：节点拖拽与整体平移

原有“修改”只能改名称和图层，几何一旦画完就无法调整，而这恰恰是“交互编辑”的核心。本次补上完整的几何编辑。

关键抽象是**统一的下标路径 `path`**，用同一套代码寻址任意几何的任意坐标：

| 几何类型 | `path` 形式 |
| --- | --- |
| Point | `[]`（coordinates 本身就是坐标） |
| LineString | `[i]` |
| MultiLineString | `[lineIdx, pointIdx]` |
| Polygon | `[ringIdx, pointIdx]` |
| MultiPolygon | `[polyIdx, ringIdx, pointIdx]` |

配套 `getByPath` / `setByPath` / `extractVertices()`，因此点、线、多线、面、多面可以共用同一套拖拽实现。支持的操作：

| 操作 | 效果 |
| --- | --- |
| 拖动节点手柄 | 移动该节点；拖动外环首节点时同步尾部重复点，保持环闭合 |
| 拖动要素本体 | 整体平移（递归平移全部坐标对） |
| 双击边 | 在最近处插入一个节点 |
| `Alt` + 点击节点 | 删除节点 |
| `Ctrl+Z` | 撤销上一步几何编辑（保留最近 30 步） |
| `Esc` | 放弃本次拖动 |

几处细节：洞环（`ringIdx > 0`）渲染为只读虚点、不参与拖拽，避免拖坏洞结构；删除节点前会先检查几何是否仍然合法（线至少 2 个节点、面环至少 3 个不重复节点），不合法就直接给出提示而不是等后端报错；`Ctrl+Z` 与原有的“撤销草图节点”共用同一个快捷键，有草图时撤销草图，否则撤销几何编辑。

#### 4. 字段级增删

属性表标题栏的“新增字段”可以为全部要素加一列并落库；表头字段名旁的 `×` 可以把该列从全部要素中删除。`ID` 和 `几何类型` 是派生列，不提供 `×`。这两类操作都通过 `POST /api/save` 整体提交。

#### 5. 遇到的问题与定位过程

**5.1 Shapefile 导入后 DBF 属性完全不可见（最严重的一个）。**
导入省级行政区 Shapefile 后，要素能画出来，但属性表里名称列全空、图层全部显示“未命名”，真实的 `NAME` / `AREA` / `CODE` 一个都看不到。定位过程：先确认后端 `read_dbf_records` 已经把 DBF 字段原样写进 `properties`，且 `normalise_feature_collection` **只补 `id` 和 `properties`，不注入 `layer` / `name` / `kind`**（全文件搜 `"layer"` 只出现在内置的 `SAMPLE_DATA` 里）；再回看前端属性表的列是写死的 `[id, name, layer, geometry.type]`。也就是说数据一直都在，只是界面上根本没有对应的列。修复方式就是把列改成由 `properties` 的键动态生成——这也是 1. 里 `collectFields()` 的由来。验证时用一个自造的 `NAME/AREA/CODE` Shapefile 导入，属性表出现了三列真实的 DBF 字段，中文属性值经由 `.cpg` 声明的 GBK 也正确解码。

**5.2 属性编辑表单对导入数据静默失效。**
即 2. 中描述的固定 `<option>` 问题。因为它不报错、只是把值变成空字符串，属于比较容易漏掉的一类缺陷。

**5.3 万级要素渲染。**
`MAX_FEATURES` 是 10000，把全部要素一次性渲染成 DOM 行会让页面卡死。权衡后选择了每页 100 行的分页，而不是引入虚拟滚动，理由是分页在这个规模下更简单、也更容易在演示时讲清楚。

**5.4 Python 3.8 兼容。**
联调时发现删除数据集会返回 500：`'str' object has no attribute 'removeprefix'`。`str.removeprefix` / `str.removesuffix` 是 Python 3.9 才有的，而本机通过 `py` 启动器只能找到 3.8.8，README 里也没有写明版本要求。受影响的是 `GET /api/datasets/{id}`、`POST /api/datasets/{id}/activate` 和 `DELETE /api/datasets/{id}` 三个接口，也就是“数据集切换”和“数据集删除”都会失败。因此在 `server.py` 顶部加了两个等价切片实现的兼容函数 `remove_prefix` / `remove_suffix` 替换这三处调用，在 3.9+ 上行为完全一致。

另外两个在实现过程中发现并修掉的问题：

- **闭合环删点会破坏闭合。** 面的环首尾是同一个重复点，直接 `splice` 掉一个位置会让首尾不再相等，后端会以 `Polygon rings must be closed` 拒绝。改为先拆出“不重复的点”，删掉目标点后再重新闭合。
- **拖拽之后浏览器还会补一个 `click`。** 这个补发的 `click` 会把刚拖完的编辑目标切掉，因此加了一个一次性的 `skipClickOnce` 标记来吞掉它；同时给全局快捷键加上输入框判断，避免在单元格里按 `Ctrl+Z` 或 `Esc` 触发地图操作。

## D 组：数据库与空间分析模块

D 组负责构建 GIS Demo 的空间分析能力，将数据导入、矢量编辑、空间计算与分析结果落库串联为完整工作流。模块面向当前数据集提供距离、面积、缓冲区和相交查询，并将结果重新纳入图层、属性表、编辑和导出体系，使系统从矢量数据编辑工具进一步升级为轻量 GIS 分析工作台。

### D 组工作目标

- 建立统一的空间分析服务层，为前端提供稳定、可组合的测量与查询接口。
- 根据坐标参考语义选择球面或平面计算模型，避免经纬度坐标与米制距离混用。
- 覆盖 Point、LineString、Polygon 及多部件几何的缓冲区和空间关系判断。
- 将分析结果自动写回当前 GeoJSON 数据集，支持后续编辑、筛选、联动和导出。
- 通过自动化测试覆盖核心几何算法，为后续真实数据接入和持续迭代提供保障。

### D 组后端接口与数据闭环

| 接口 | 核心职责 | 输出结果 |
| --- | --- | --- |
| `POST /api/spatial/measure` | 执行距离或面积测量 | 数值、单位、坐标语义和要素类型提示 |
| `POST /api/spatial/buffer` | 根据要素和距离生成缓冲区 | GeoJSON Polygon / MultiPolygon 要素 |
| `POST /api/spatial/intersects` | 查询当前数据集中与源要素相交的要素 | 相交要素 ID 和完整要素信息 |

接口统一复用当前数据集读取、GeoJSON 校验、要素更新和原子保存逻辑。缓冲区结果会自动写入当前数据集，并记录 `source_id`、`distance`、`distance_unit` 和 `analysis` 等元数据，与普通编辑要素共享同一生命周期。

### D 组核心算法设计

- **坐标语义与测量模型**：WGS 84 经纬度使用 Haversine 球面距离和球面环面积近似，结果分别以米和平方米表达；模拟 / 投影坐标使用平面欧氏长度和鞋带公式，单位跟随输入坐标。
- **点线面缓冲区**：Point 生成近似圆形 Polygon；LineString 生成带圆形端帽的缓冲面；Polygon 对外环向外偏移、对洞环向内偏移；多部件几何按组件生成 Polygon 或 MultiPolygon。WGS 84 数据先进行局部方位等距投影，再反投影回经纬度。
- **相交关系判断**：覆盖线段相交、点在线段上、点在 Polygon 外环内且不在洞内，以及 Polygon 边界相交和相互包含等关系。

当前实现坚持零第三方依赖，适合课程 Demo、交互演示和常见简单几何；复杂自交、多洞拓扑修复及相邻缓冲面融合，后续可接入 Shapely / GEOS 提升拓扑精度。

分析结果可以继续被点选、框选、编辑几何、修改属性、删除、切换图层显隐并导出，形成从空间计算到可视化反馈的闭环。

### 10.16号D 组新增功能：道路网络最短路径分析模块

D 组在原有 GIS Demo 距离测量、面积计算、缓冲区分析和空间相交查询的基础上，进一步扩展了道路网络空间分析能力，新增基于 **Dijkstra 算法的最短路径分析模块**。模块以 OpenStreetMap 道路矢量数据为基础，将 GeoJSON 线状道路转换为具有拓扑连接关系的网络图结构，实现了道路数据加载、交互式起终点选择、最短路径求解、路径距离计算和地图高亮展示的完整分析流程。

模块采用独立式开发与接入方式，在保留原有地图显示、矢量编辑和空间分析功能的前提下，新增道路网络分析能力，无需依赖 PostGIS、Docker 或其他第三方数据库，适合本地部署与小组协作演示。

#### D 组工作目标

- 构建基于 GeoJSON 道路矢量数据的空间网络分析模块，支持 LineString 和 MultiLineString 几何类型。
- 将道路的空间坐标及拓扑连接关系转换为图结构，实现道路节点、边及权重的自动构建。
- 基于 Dijkstra 最短路径算法，计算指定起点与终点之间沿道路网络的最短通行距离。
- 实现地图交互式选点与道路自动吸附，支持用户通过鼠标确定起点、终点并执行路径求解。
- 将最短路径结果以 GeoJSON LineString 形式返回，并在地图中高亮显示，同时输出路径长度。
- 保持模块独立性，避免影响原有图层管理、属性编辑、空间量算和缓冲区分析等功能。

#### D 组后端接口与路径分析流程

| 接口 | 核心职责 | 输出结果 |
| --- | --- | --- |
| `GET /api/routing/network` | 读取当前道路网络数据 | GeoJSON 路网、节点数量、边数量及空间范围 |
| `POST /api/routing/solve` | 根据起终点执行最短路径求解 | 最短路径 GeoJSON、路径长度、吸附信息及搜索节点数 |
| `POST /api/routing/network` | 导入并校验自定义 GeoJSON 路网 | 路网节点、边及道路要素统计信息 |
| `DELETE /api/routing/network` | 清除自定义路网配置并恢复内置示例 | 路网恢复状态 |

后端通过 `routing.py` 实现路网构建和路径计算，通过 `route_api.py` 封装独立的 HTTP 接口，并与现有 `server.py` 进行集成。

模块内置基于 OpenStreetMap 的首尔道路 GeoJSON 节选数据，同时支持用户上传符合 WGS 84 坐标要求的自定义道路数据。导入后的路网经过几何类型与坐标有效性校验，作为后续路径分析的数据来源。

路径求解完成后，系统以 GeoJSON LineString 形式返回路线几何和米制距离，通过前端 Canvas 进行可视化叠加，形成从道路数据读取、网络构建、路径计算到结果展示的分析流程。

#### D 组核心算法设计

- **道路网络拓扑构建**：将 GeoJSON 中的 LineString 和 MultiLineString 道路拆分为连续线段，以道路坐标节点构建图的顶点，以相邻节点之间的道路段构建边。根据共享道路节点建立拓扑连接关系，避免将没有共享节点的交叉线段错误识别为可通行路口。
- **道路长度与权重计算**：针对 WGS 84 经纬度数据，采用 Haversine 球面距离公式计算相邻道路节点之间的近似地表距离，并将结果转换为米，作为图结构中各条边的权重。
- **Dijkstra 最短路径算法**：采用优先队列与邻接表结构，从起点开始逐步更新相邻节点的累计距离，寻找通往终点的最小权重路径。通过前驱节点记录与回溯，还原完整的最短道路路径。
- **道路自动吸附与中间点处理**：对用户选择的起终点计算其在邻近道路段上的投影位置，并将吸附点临时接入道路网络。支持起点和终点位于道路中间位置的情况，避免仅以道路端点作为路径分析起终点而产生不必要的绕行。
- **异常情况处理**：对无效 GeoJSON、非支持坐标系、超出道路吸附范围以及不连通路网进行校验和提示，避免生成无效路线。

当前算法以双向道路网络的几何长度作为优化目标，适用于课程教学与基础路径分析场景。尚未考虑单行道、交通管制、转向限制及实时交通状态，后续可结合道路属性扩展为更加完整的交通网络分析模型。

### 10.23号D 组新增功能：障碍面约束下的最短路径分析与自动重算

D 组在 10.16 号完成的道路网络最短路径分析模块基础上，进一步扩展了路径分析的空间约束能力，新增**障碍面绘制、道路阻断判断和最短路径自动重算功能**。用户可以在地图中绘制多边形障碍区域，模拟道路施工、区域封闭等不可通行范围。系统根据道路与障碍面的空间关系，排除受阻道路，并基于 **Dijkstra 算法**重新计算起点与终点之间的最短可通行路径。

本次功能延续独立式开发与接入方式，在原有最短路径分析面板中增加障碍面操作工具，实现从初始路径求解、障碍区域绘制、受阻道路判断到绕行结果展示的完整流程。后端继续使用 Python 标准库，无需依赖 PostGIS、Docker 或其他第三方数据库，适合本地部署与小组协作演示。

#### D 组工作目标

- 在原有最短路径分析窗口中新增“添加障碍面”功能，支持用户通过地图点击绘制多边形障碍区域。
- 实现障碍面有效性校验，识别自相交、重复顶点、折返重叠边和零面积等无效几何。
- 判断道路与障碍面的空间关系，将穿越障碍区域、位于其内部或接触其边界的道路段视为不可通行。
- 在保留当前起终点的情况下，添加、移除或清空障碍面后自动重新计算最短路径。
- 支持多个障碍面共同参与路径分析，实现多区域约束下的道路绕行。
- 提供撤销节点、取消绘制、移除上一个障碍面和清空全部障碍面的操作。
- 完善起终点被覆盖、全部路径被阻断及异步结果过期等情况的处理，避免展示无效路线。
- 保持障碍分析与原有 GIS 数据编辑相互独立，避免分析操作修改用户数据集。

#### D 组后端接口与路径分析流程

本次开发复用原有道路网络接口，重点扩展最短路径求解接口的请求参数与计算逻辑。

| 接口 | 核心职责 | 输出结果 |
| --- | --- | --- |
| `GET /api/routing/network` | 读取内置、自定义或指定数据集路网 | GeoJSON 路网、节点数量、边数量及空间范围 |
| `POST /api/routing/solve` | 根据起终点与障碍面执行避障最短路径求解 | 最短路径 GeoJSON、路径长度、吸附信息、搜索节点数及障碍统计 |
| `POST /api/routing/network` | 导入并校验自定义 GeoJSON 路网 | 路网节点、边及道路要素统计信息 |
| `DELETE /api/routing/network` | 清除自定义路网配置并恢复内置示例 | 路网恢复状态 |

后端通过 `routing.py` 实现障碍面几何校验、道路阻断判断及避障路径计算，通过 `route_api.py` 扩展原有求解接口，并继续使用现有 `server.py` 的接入机制。

`POST /api/routing/solve` 在原有 `start`、`end` 参数基础上，新增 `obstacles` 参数，用于传递 GeoJSON Polygon 障碍面列表。省略该参数时，系统仍按照原有方式计算最短路径，保持接口兼容性。

路径分析时，系统首先校验障碍面并将起终点吸附到原始道路，检查吸附点是否受到障碍覆盖，再根据道路与障碍面的空间关系过滤受阻道路，最后在剩余可通行网络中执行 Dijkstra 搜索。求解成功后，除原有路线和距离外，返回 `obstacle_count` 与 `blocked_edges`，分别表示参与计算的障碍面数量和被阻断的原始道路分段数量。

本次同时修复“用当前数据集作为路网”时，路径求解请求遗漏 `dataset_id` 的问题，确保路网展示、手动求解与障碍更新后的自动重算使用同一个数据来源。

#### D 组核心算法设计

- **障碍面几何校验**：检查 Polygon 类型、WGS 84 坐标有效性、环闭合、顶点数量及面积，拒绝自相交、连续重复顶点和折返重叠边等无效输入，避免错误几何影响路径计算。
- **点面位置与线段相交判断**：结合点在多边形中的位置判断和线段相交判断，识别道路穿越障碍面、完全处于障碍内部、与边界相切或沿边界重叠等情况。障碍面内部与边界均按不可通行处理。
- **空间范围预筛选**：先比较道路段与障碍面的外包范围，仅对可能接触的对象进行进一步几何判断，减少不必要的计算。
- **障碍约束下的 Dijkstra 算法**：保留原有 Haversine 道路长度权重，在搜索过程中跳过受阻道路，计算多个障碍面共同约束下的最短可通行路线。
- **道路中间吸附点的局部通行处理**：对起终点与道路端点之间的临时连接段分别进行障碍判断。即使原始道路边的其他部分受到阻挡，只要实际经过的局部路段未受影响，仍允许通行，避免过度阻断。
- **路网缓存与数据保护**：受阻道路仅在当前请求中进行过滤，不永久删除道路或修改缓存图结构。移除障碍面后，可以恢复原有路网条件下的路径求解。
- **异常情况处理**：当起终点位于障碍面内部或边界上时，提示调整障碍或重新选点；当全部路线被切断时，返回无可通行路径提示，并由前端清除旧路线。

后端同时支持带洞 Polygon，洞内区域作为可通行空间，洞的边界仍不可通行；前端新增绘制工具用于创建单外环多边形。

当前算法继续以双向道路网络的几何长度为优化目标。障碍面表示禁止通行的空间区域，尚未进一步考虑单行道、转向限制、实时交通及不同道路通行成本。

#### D 组前端交互设计

在原有“最短路径分析”窗口中新增障碍面工具区，显示当前障碍数量，并提供绘制与管理按钮。前端支持以下操作：

1. 点击“↗ 最短路径”，加载道路网络，并在道路上依次选择起点和终点。
2. 点击“求解最短路径”，获取初始路线及距离。
3. 点击“添加障碍面”，进入独立的多边形绘制状态，在地图上依次放置至少三个顶点。
4. 点击“完成障碍面”，或通过双击、Enter 键、点击首个顶点完成闭合。
5. 将已完成的障碍面以红色半透明区域显示在地图中，绘制过程中显示虚线草稿和顶点标记。
6. 已选好起终点时，完成障碍面后自动重新计算，无需再次点击求解；以橙红色线条展示更新后的路线，并显示距离和障碍统计。
7. 绘制中支持“撤销节点”及 `Ctrl/Cmd+Z`，支持“取消绘制”或 Esc 放弃当前草稿。
8. 支持连续添加多个障碍面，点击“移除上一个”或“清空障碍”后自动重新求解。
9. 支持先绘制障碍面再选择起终点；点击“重选”时保留已完成的障碍面，切换路网时清空原有起终点与障碍。
10. 求解失败时清除旧路径，通过请求取消与版本校验，防止旧结果覆盖新状态；面板增加滚动适配，使较小窗口中的操作按钮仍可访问。

前端继续使用独立的 `route-addon.js` 和 `route-addon.css`，障碍面仅保留在本次页面的分析状态中，不写入原有 GIS 数据集。当前最多支持 20 个障碍面，合计最多 500 个坐标点，包含闭合点；刷新页面后清除本次障碍。
