# GIS 矢量数据编辑与管理 Demo

这是一个用于“GIS 算法与应用”第一次作业展示的最小可运行版本。

## 功能

- 图层显示与显隐控制
- 鼠标交互录入点、线、面
- 地图漫游、缩放、全图显示
- 点选、框选与属性表查看
- 底部全宽属性表：按数据动态生成列、双击单元格行内编辑、过滤 / 搜索 / 分页
- 几何编辑：拖动节点改形状、整体平移要素、双击边插入节点、`Alt` + 点击删除节点、`Ctrl+Z` 撤销
- 属性字段的新增与删除，并写入全部要素落库
- 坐标实时读数、图层统计与选中要素删除
- 响应式工作台布局，支持桌面与窄屏展示
- Python 后端保存 GeoJSON
- GeoJSON 导出
- GeoJSON 文件导入、数据集切换与文件元数据登记
- Shapefile ZIP/成套文件导入、SHP/DBF/PRJ/CPG 解析与 GeoJSON 转换
- PostGIS 留出后续扩展位置

## 运行

```bash
python server.py 8000
```

后端只使用 Python 标准库，Python 3.8 及以上都可以直接运行。

然后打开：

```text
http://127.0.0.1:8000
```

## 操作说明

1. 在左侧设置要素名称和图层，再选择“画点 / 画线 / 画面”。
2. 画线和画面需要连续点击地图，完成后点击“完成绘制”。
3. 使用“点选”或“框选”查看属性；单选后右侧表单会按该要素的真实字段渲染，可以直接改值并保存，删除操作会立即写入当前 GeoJSON。
4. 画线或画面过程中可以撤销节点，也可以按 `Esc` 取消绘制。
5. “全图”会根据当前数据范围自动计算合适的视图。
6. 地图下方的“属性表”抽屉列出当前数据集的全部要素。双击任意单元格即可就地改值，`Enter` 或点击别处提交，`Esc` 取消；拖动“全部 / 仅选中”可以只看选中要素，搜索框按任意字段值过滤，行内 `Ctrl` / `Shift` 点击可以加选和范围选，并与地图选中状态联动。
7. 选中要素后切换到“编辑几何”：拖动方形手柄改变形状，拖动要素本体整体平移，双击边插入节点，`Alt` + 点击节点删除节点，`Ctrl+Z` 撤销上一步几何编辑，`Esc` 放弃本次拖动。每一步结束都会自动写回后端。
8. 属性表标题栏的“新增字段”可以为全部要素加一列，表头字段名旁的 `×` 可以把该列从全部要素中删掉。

## A 组：后端文件数据模块（当前实现）

后端现在提供一个轻量的数据集目录。导入的文件会存放在运行时目录 `data/uploads/`，并自动登记文件元数据：

- `GET /api/datasets`：列出数据集、当前激活数据集和要素统计。
- `POST /api/datasets/import`：导入 GeoJSON/JSON、Shapefile ZIP 或成套 `.shp/.shx/.dbf/.prj/.cpg` 文件，并自动切换为当前数据集。
- `POST /api/datasets/{id}/activate`：切换当前数据集。
- `GET /api/datasets/{id}`：读取指定数据集和元数据。
- `DELETE /api/datasets/{id}`：删除非当前数据集，至少保留一个数据集。
- `GET /api/layers`：读取当前数据集，供地图显示。
- `POST /api/save`、`POST /api/features`：保存当前数据集或追加要素。
- `PUT /api/features/{id}`、`DELETE /api/features/{id}`：更新或删除当前数据集中的要素。
- `GET /api/export`：导出当前数据集。

导入和保存过程会检查文件大小、要素数量、要素 ID、几何类型、坐标数值和面环闭合情况；缺少 ID 的导入要素会由后端自动生成唯一 ID。Shapefile 导入既支持 ZIP，也支持在文件选择器中同时选择同名的 `.shp/.shx/.dbf/.prj/.cpg` 文件；直接选择成套文件时至少需要 `.shp/.shx/.dbf`，`.prj/.cpg` 为可选。ZIP 会自动忽略 `__MACOSX`、`._*` 等系统隐藏文件；如果 ZIP 中没有 Shapefile 但只有一个 GeoJSON/JSON 文件，也会按 GeoJSON 导入。后端读取 `.shp` 几何、`.dbf` 属性、`.cpg` 编码和 `.prj` 坐标系提示，并统一转换为内部 GeoJSON 数据集；空几何记录会被跳过。当前支持 Point、PolyLine 和 Polygon 三类 Shapefile，单个组件最大 20 MB。

前端的数据文件面板支持查看文件大小、来源格式、几何类型、bbox 和坐标系提示，并可切换或删除非当前数据集。

这部分已经形成“文件导入 → 格式校验/转换 → 元数据登记 → 数据集切换 → 地图读取 → 文件管理”的后端闭环。当前 `.prj` 只做坐标系提示，还没有进行 Albers 等投影到经纬度的坐标转换；下一步可以继续扩展完整的 CRS/EPSG 转换、复杂 Polygon 洞结构和数据库存储。

### A 组本次工作详细记录

本次 A 组主要负责后端文件数据模块的完善，目标是让 Demo 能够接收真实 GIS 文件，将不同来源的矢量数据统一转换成系统内部使用的 GeoJSON，并交给前端地图进行显示和管理。具体完成内容如下。

#### 1. 完善 GeoJSON/JSON 数据导入流程

- 后端接收 `.geojson` 和 `.json` 文件，并检查文件是否为标准 `FeatureCollection`。
- 对导入数据中的 Feature、geometry、coordinates、属性字段和要素数量进行基本校验。
- 对缺少唯一 ID 的要素自动生成 ID，避免前端选中、修改和删除时无法定位对象。
- 导入成功后，将数据写入 `data/uploads/`，同时在数据集目录中登记文件名、数据大小、要素数量、几何类型、bbox、坐标系提示和创建时间。
- 导入的数据会自动设为当前数据集，前端地图随后重新读取并显示。

#### 2. 新增 Shapefile ZIP 导入

Shapefile 不是单独一个文件，而是由同名的 `.shp`、`.shx`、`.dbf` 文件组成，通常还会包含 `.prj` 和 `.cpg`。本次在不依赖第三方 GIS 库的情况下，使用 Python 标准库完成了基础解析：

- `.shp`：读取 Point、PolyLine 和 Polygon 的几何坐标。
- `.dbf`：读取属性表字段和值，并将属性挂接到对应 Feature。
- `.prj`：读取坐标系描述，记录为数据集的坐标系提示。
- `.cpg`：识别 UTF-8、GBK、GB2312 等常见编码，改善中文属性字段和中文属性值的读取。
- 支持 Polygon 的多个环，并在必要时转换为 `MultiPolygon`。
- 跳过 Shapefile 中的空几何记录，避免个别空记录导致整个图层无法导入。
- 对 ZIP 中的隐藏系统文件（如 `__MACOSX`、`._*`、`.DS_Store`）进行过滤。
- 当 ZIP 中只有一个 GeoJSON/JSON 文件而没有 `.shp` 时，也可以按 GeoJSON ZIP 进行导入。

导入后，Shapefile 不会直接以原始二进制文件参与前端绘制，而是被转换为标准 GeoJSON，再复用现有的数据集管理和地图渲染流程。这样可以保持前后端数据格式统一。

#### 3. 新增成套 Shapefile 文件直接导入

除了 ZIP 导入，前端文件选择器现在支持同时选择同名的：

```text
省级行政区.shp
省级行政区.shx
省级行政区.dbf
省级行政区.prj
省级行政区.cpg（可选）
```

前端会自动识别 `.shp` 主文件，并收集同名的配套文件，以 Base64 形式发送给后端。后端至少要求 `.shp`、`.shx`、`.dbf` 三个文件，`.prj` 和 `.cpg` 为可选文件。这样用户既可以上传 ZIP，也可以直接选择 GIS 软件导出的完整文件组。

#### 4. 完善数据集管理和前端反馈

- 数据文件面板显示当前数据集、数据来源格式、要素数量、几何类型、bbox 和坐标系提示。
- 支持在多个已导入数据集之间切换。
- 支持删除非当前数据集，避免误删当前正在使用的数据。
- 上传过程中显示“正在导入”状态，导入成功后显示要素数量和数据格式。
- 导入失败时直接显示后端返回的错误原因，例如缺少 `.shx` 或 `.dbf`、ZIP 中没有 `.shp`、文件格式不符合要求等。
- 上传期间暂时禁用文件选择控件，避免重复提交或同时导入多个文件造成状态混乱。

#### 5. 修复真实投影坐标数据显示问题

在使用桌面上的真实省级行政区 Shapefile 测试时，文件能够成功解析并显示 34 个面要素，但地图最初仍然是空白。排查后发现，数据使用的是投影坐标，坐标值达到数百万，例如：

```text
X 范围约为 -2578821 至 2092054
Y 范围约为 2367106 至 6385320
```

原地图的全图缩放函数将最小缩放比例限制为 `0.25`，不适合这种大范围投影坐标，导致要素被计算到画布可视区域之外。此次将缩放下限调整为更小的动态范围，使地图能够根据真实数据 bbox 自动适配。修复后，34 个省级行政区可以正常显示在画布中。

需要说明的是，当前版本已经可以读取并显示投影坐标，但 `.prj` 目前主要用于识别和提示坐标系，还没有完成 Albers 等投影坐标到 WGS 84 经纬度的转换。当前地图因此更适合作为文件导入、数据管理和几何显示 Demo；如果后续需要与在线底图叠加，还需要引入 `pyproj` 等工具完成 CRS/EPSG 转换。

本次使用真实桌面数据进行了以下验证：

- `测试数据.zip`：成功导入 34 个 Polygon/MultiPolygon 要素。
- `省级行政区.shp + .shx + .dbf + .prj`：成功导入 34 个 Polygon/MultiPolygon 要素。
- 导入后的属性数据、几何类型、要素数量和 bbox 能够写入数据集目录。
- 导入成功后会自动切换当前数据集。
- 前端图层列表显示 34 个要素，地图可以正常绘制省级行政区边界。
- JavaScript 语法检查通过，Python 源码 AST 检查通过。

## B 组：交互编辑与属性模块

这部分负责“在浏览器里把矢量数据改对”，即画点线面之后的完整编辑链路：底部属性表、行内改值与字段增删、点选 / 框选、以及新增的几何编辑（节点拖拽 + 整体平移）。全部改动都在前端 `static/` 下完成，后端只补了一处 Python 3.8 兼容层（见 5.4），要素的写入仍然统一走已有的 `PUT /api/features/{id}` 和 `POST /api/save`。

### B 组本次工作详细记录

本次 B 组主要负责交互编辑与属性模块。原有版本已经能画点线面、点选框选和查看属性，但属性表是一层写死的表格，几何一旦落笔就再也改不动。本次先把属性表做成由数据驱动的全宽表格，再补上几何编辑能力。具体完成内容如下。

#### 1. 把属性表做成底部全宽抽屉

右侧属性栏只有 326px 宽，放不下真实数据的多字段表格，因此把完整属性表移到地图下方，做成可折叠的全宽抽屉，交互方式对标 QGIS / ArcGIS。

- 列不再写死。`collectFields()` 取当前数据集全部要素 `properties` 键的并集作为列，`名称` / `图层` 排在前面，其余按首次出现顺序（利用 `Array.prototype.sort` 在 V8 中的稳定性），再加一列 `几何类型`。
- 双击任意单元格，原地换成输入框修改；`Enter` 或失焦提交，`Esc` 取消。提交后走已有的 `PUT /api/features/{id}`，立即落库。
- 值类型保持：原值是数字且新文本可以解析为有限数字时仍然存数字，其余存字符串，避免面积、代码这类字段被整体变成字符串。
- 分页：`MAX_FEATURES` 上限是 10000，一次性渲染会卡死，因此按每页 100 行分页，底部显示“第 X / Y 页 · 本页 N 行”。
- 过滤与搜索：可以在“全部 / 仅选中”之间切换，也可以按任意字段值搜索。
- 与地图联动：点击行即选中该要素，`Ctrl` / `Shift` 点击可以加选和范围选，高亮状态与画布上的选中状态双向同步。

#### 2. 属性编辑表单改为按真实字段渲染

原来右侧编辑表单固定显示“名称”和“图层”两个控件，其中图层是一个含 5 个固定 `<option>` 的下拉框。这个设计对导入数据是失效的：Shapefile 的 `properties` 里根本没有 `layer` 字段（只有 DBF 的真实字段），字段名也不在固定选项里，赋值后会被静默清空。

现在改为按选中要素的真实字段动态渲染，一行一个输入框；`layer` 仍然用 `<input list="layerOptions">` 加由现有图层名填充的 `<datalist>`，既能选已有图层，也能直接输入新图层名。导入数据因此第一次可以在右侧正常编辑。

#### 3. 新增几何编辑：节点拖拽与整体平移

原有“修改”只能改名称和图层，几何一旦画完就无法调整，而这恰恰是“交互编辑”的核心。本次补上完整的几何编辑。

关键抽象是**统一的下标路径 `path`**，用同一套代码寻址任意几何的任意坐标：

| 几何类型 | `path` 形式 |
| --- | --- |
| Point | `[]`（coordinates 本身就是坐标） |
| LineString | `[i]` |
| MultiLineString | `[lineIdx, pointIdx]` |
| Polygon | `[ringIdx, pointIdx]` |
| MultiPolygon | `[polyIdx, ringIdx, pointIdx]` |

配套 `getByPath` / `setByPath` / `extractVertices()`，因此点、线、多线、面、多面可以共用同一套拖拽实现。支持的操作：

| 操作 | 效果 |
| --- | --- |
| 拖动节点手柄 | 移动该节点；拖动外环首节点时同步尾部重复点，保持环闭合 |
| 拖动要素本体 | 整体平移（递归平移全部坐标对） |
| 双击边 | 在最近处插入一个节点 |
| `Alt` + 点击节点 | 删除节点 |
| `Ctrl+Z` | 撤销上一步几何编辑（保留最近 30 步） |
| `Esc` | 放弃本次拖动 |

几处细节：洞环（`ringIdx > 0`）渲染为只读虚点、不参与拖拽，避免拖坏洞结构；删除节点前会先检查几何是否仍然合法（线至少 2 个节点、面环至少 3 个不重复节点），不合法就直接给出提示而不是等后端报错；`Ctrl+Z` 与原有的“撤销草图节点”共用同一个快捷键，有草图时撤销草图，否则撤销几何编辑。

#### 4. 字段级增删

属性表标题栏的“新增字段”可以为全部要素加一列并落库；表头字段名旁的 `×` 可以把该列从全部要素中删除。`ID` 和 `几何类型` 是派生列，不提供 `×`。这两类操作都通过 `POST /api/save` 整体提交。

#### 5. 遇到的问题与定位过程

**5.1 Shapefile 导入后 DBF 属性完全不可见（最严重的一个）。**
导入省级行政区 Shapefile 后，要素能画出来，但属性表里名称列全空、图层全部显示“未命名”，真实的 `NAME` / `AREA` / `CODE` 一个都看不到。定位过程：先确认后端 `read_dbf_records` 已经把 DBF 字段原样写进 `properties`，且 `normalise_feature_collection` **只补 `id` 和 `properties`，不注入 `layer` / `name` / `kind`**（全文件搜 `"layer"` 只出现在内置的 `SAMPLE_DATA` 里）；再回看前端属性表的列是写死的 `[id, name, layer, geometry.type]`。也就是说数据一直都在，只是界面上根本没有对应的列。修复方式就是把列改成由 `properties` 的键动态生成——这也是 1. 里 `collectFields()` 的由来。验证时用一个自造的 `NAME/AREA/CODE` Shapefile 导入，属性表出现了三列真实的 DBF 字段，中文属性值经由 `.cpg` 声明的 GBK 也正确解码。

**5.2 属性编辑表单对导入数据静默失效。**
即 2. 中描述的固定 `<option>` 问题。因为它不报错、只是把值变成空字符串，属于比较容易漏掉的一类缺陷。

**5.3 万级要素渲染。**
`MAX_FEATURES` 是 10000，把全部要素一次性渲染成 DOM 行会让页面卡死。权衡后选择了每页 100 行的分页，而不是引入虚拟滚动，理由是分页在这个规模下更简单、也更容易在演示时讲清楚。

**5.4 Python 3.8 兼容。**
联调时发现删除数据集会返回 500：`'str' object has no attribute 'removeprefix'`。`str.removeprefix` / `str.removesuffix` 是 Python 3.9 才有的，而本机通过 `py` 启动器只能找到 3.8.8，README 里也没有写明版本要求。受影响的是 `GET /api/datasets/{id}`、`POST /api/datasets/{id}/activate` 和 `DELETE /api/datasets/{id}` 三个接口，也就是“数据集切换”和“数据集删除”都会失败。因此在 `server.py` 顶部加了两个等价切片实现的兼容函数 `remove_prefix` / `remove_suffix` 替换这三处调用，在 3.9+ 上行为完全一致。

另外两个在实现过程中发现并修掉的问题：

- **闭合环删点会破坏闭合。** 面的环首尾是同一个重复点，直接 `splice` 掉一个位置会让首尾不再相等，后端会以 `Polygon rings must be closed` 拒绝。改为先拆出“不重复的点”，删掉目标点后再重新闭合。
- **拖拽之后浏览器还会补一个 `click`。** 这个补发的 `click` 会把刚拖完的编辑目标切掉，因此加了一个一次性的 `skipClickOnce` 标记来吞掉它；同时给全局快捷键加上输入框判断，避免在单元格里按 `Ctrl+Z` 或 `Esc` 触发地图操作。

#### 6. 本次测试结果

在 `python server.py 8000` + 浏览器中逐项验证，结论如下。

- **默认数据**：底部属性表列出 5 个要素，列为 `ID / 名称 / 图层 / 几何类别 / 几何类型`，分页信息显示“第 1 / 1 页 · 本页 5 行”。
